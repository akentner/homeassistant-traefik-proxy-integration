<objective>
Two small, independent pre-push fixes on branch `feat/marketplace-polish`, both decided in the decision log as M44
("Vor dem Push per /gsd-quick: IN-03 (UnicodeError aus getaddrinfo => DNS-Fehlerpfad) + persist-credentials: false").

1. Phase 8 review finding IN-03: `socket.getaddrinfo` raises `UnicodeError` (Python 3.14: `UnicodeEncodeError`,
   message "'idna' codec can't encode characters in position 0-63: label too long", verified locally) for a host label
   longer than 63 characters or invalid IDNA. `UnicodeError` is a `ValueError`, not an `OSError`, so it escapes
   `CertCoordinator._async_resolve_connect_addresses` (cert_coordinator.py:389-403), aborts the whole cycle in
   `_async_update_data` (switches to the retry interval, HA logs an unexpected error and every cert entity goes
   unavailable). Fix: treat it like the existing `socket.gaierror` path, so every host gets a `dns` probe failure.
   Regression introduced in Phase 8 (WR-02 resolver, commit ca1f5eb) and never released, so no CHANGELOG entry.
2. Set `persist-credentials: false` on all six `actions/checkout` steps; no job needs the persisted git token.

Purpose: the cert cycle never crashes on a malformed Traefik host name (core value: certificate health stays visible),
and no CI job leaves a GITHUB_TOKEN in `.git/config` where later steps or third-party containers (hassfest image
`:latest`, hacs/action image `:main`, both mounting the workspace) could read it.
Output: two atomic commits (IN-03 code + test + disposition; workflows), then SUMMARY.md.
</objective>

- `CertCoordinator._async_resolve_connect_addresses(self, host: str) -> list[str] | ProbeFailure`

    `asyncio.timeout(self._timeout)`.
  - Current clauses in order: `except socket.gaierror as err` -> `ProbeFailure(ProbeError.DNS, f"{type(err).__name__}: {err}")`;
    `except TimeoutError` -> TIMEOUT; `except OSError` -> OSERROR; empty answer -> `ProbeFailure(ProbeError.DNS, "no address")`.
- `tls.py` is NOT a resolution site: `async_probe_certificate` always receives an address (resolved or IP literal)
  as `connect_host`. Do not change `tls.py` or `tls._ERROR_CLASSES`.
