<objective>
Close verification gap G6 (review CR-01, blocker) and the two review warnings WR-01 and WR-02 of Phase 5, so that "existing installs are migrated cleanly" holds and no lifecycle path deletes or duplicates something the user still relies on.

Purpose:
- **CR-01 / G6 (ENT-09, D-18):** the 1.1 -> 1.2 migration currently brings every router the user disabled in 0.3.0 back as an enabled, recording router sensor. Afterwards a disabled router stays disabled.
- **WR-01 (ENT-09):** the update listener is never unsubscribed. The migration's forced reload, 30 s after the first start, stacks duplicate and stale listeners. The fix stays minimal; a later phase removes the listener entirely (M5).
- **WR-02 (ENT-10, ENT-03, D-15):** switching per-item entities off deletes the Routers/Services sub-devices without the reference check the legacy cleanup uses. This unlinks other integrations' helper entities. User priority: never delete a device that still has entities.

Output: the fixes in `__init__.py` and `entity.py`, five new tests (one parametrized four ways, one two ways) in three test modules, and the review disposition updated to `fixed`.

Scope guards:
- IN-01..IN-04 stay open/untouched. IN-02 belongs to FLOW-07 and IN-04 to W36 in Phase 7; IN-01 and IN-03 are left for later triage.
- HA minimum stays 2026.3.0. No 2026.11-only API (M4), no `DeviceInfo(via_device=...)`, no `OptionsFlowWithReload` (that is Phase 7, M5).
- Do not push or tag (U1, M8).
</objective>

**CR-01 fix feasibility (both HA versions)**
- Pre-create, after the removal, with `registry.async_get_or_create("sensor", DOMAIN, unique_id, config_entry=entry, disabled_by=<mapped>, suggested_object_id=<old object id>)`. Result: `sensor.traefik_http_router_file_ok_file` with the mapped `disabled_by`, no state, and `device_id` re-pointed to the Routers sub-device by the platform.
- An enabled router binary sensor still yields the platform-generated `sensor.traefik_routers_traefik_example_com_file_ok_file`, enabled.
- The legacy `http_routers` device is removed afterwards by the existing cleanup.
- The full suite stayed green with the fix applied (570 = 563 + 7 probe tests).

**HA registry behaviour (2026.3 source)**
- `helpers/entity_registry.py:1398-1405`: on any update event of a device that is not disabled, HA clears `disabled_by=DEVICE` on that device's entities. A replacement must therefore never carry DEVICE.
- `async_get_or_create` on an existing entry returns it unchanged. `disabled_by` applies only when the entry is created.
- Without `suggested_object_id`, the fallback entity_id is `sensor.traefik_proxy_<entry_id>_http_router_<slug>`, which puts the entry ULID into the id.

**WR-01 reproduction**
- At HEAD: `len(entry.update_listeners)` is 1 after setup, 2 after one `async_reload`, and still 2 after `async_unload`. One options change after the reload runs the listener twice; this was measured by patching `custom_components.traefik_proxy.build_api_client` with `wraps=`.
- With `entry.async_on_unload(entry.add_update_listener(...))` the values are 1 / 1 / 0 with exactly one run, on both venvs.

**WR-02 reproduction (both HA versions)**
- A registry entry of platform `derivative`, with no config entry and `device_id` set to the Routers sub-device, is an entity of another integration.
- After options `{CONF_PER_ITEM_ENTITIES: False}` and a reload, HEAD removes the Routers sub-device and sets that entry's `device_id=None`.
- With the reference guard the Routers sub-device is kept, the foreign entry keeps its `device_id`, and the unreferenced Services sub-device is removed. Both an enabled and a USER-disabled foreign entry keep the device.

**Test-harness traps**
- `dr.async_get(hass).async_get_device(identifiers=...)` raises `RuntimeError` (deprecated) in the HA 2026.10 test harness. Find devices only through `dr.async_entries_for_config_entry`, for example with the `_devices` helper in `tests/test_devices.py`.
- `MockConfigEntry` defaults to version 1.1, so every test entry without `minor_version=2` passes through the migration.
- HA schedules an entry reload 30 s after the migration clears `disabled_by` on an aggregate. Migration tests must not advance time after setup.
- RED convention (STATE, 05-01): the RED commit marks new tests as strict expected failures, so every commit stays green. GREEN removes the markers. A test that passes at RED (an invariant case) carries no marker.
