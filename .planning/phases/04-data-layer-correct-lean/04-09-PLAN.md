<objective>
Make the paginated fallback revocable (WR-01, binding decision M27): when a single 404 on `/api/rawdata` (for example while Traefik restarts and its API router is not loaded yet) has switched the client to the paginated list endpoints, the hourly version re-check retries `/api/rawdata` once and switches back on success.

Purpose: today the switch is permanent until HA restarts or the options are saved, which costs four requests per cycle instead of one on the v3.7 capture (routers 2 pages, services 1, middlewares 1) and breaks the "one call-set per scan interval" budget (DATA-02, ROADMAP Phase 4 SC3, D-14). The request budget stays bounded: at most one extra rawdata request per hour.
Output: client probe API, coordinator arming on the hourly re-check, probe unit tests, new rows in `test_request_budget_matrix`, the D-07 amendment in 04-CONTEXT.md.
</objective>

<decision_amendment>
D-07 is amended by M27 (manager decision, 2026-11-14): the paginated choice is no longer remembered for the client's whole existence. While paginated, the coordinator cycle that performs the hourly version re-check asks the client to retry `GET /api/rawdata` once. Success switches back to rawdata; a 404 or any other non-auth failure keeps the pages; an auth failure propagates. At most one extra rawdata request per hour. This supersedes the 04-06 must-have truth "never requests /api/rawdata again for its lifetime". ROADMAP SC3 and DATA-02 stay as written (they never said lifetime). The amendment text is written into 04-CONTEXT.md by Task 2 so code and decision land together.
</decision_amendment>
