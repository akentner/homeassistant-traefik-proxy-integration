<objective>
Close gap WR-02 (DATA-04 partial, M26): aiohttp's request-construction `ValueError` ("Cannot combine AUTHORIZATION header with AUTH argument or credentials encoded in URL") must not escape the client, and the config flow steps where the user enters a new URL (user, reconfigure) must not accept credentials embedded in it. Revision 1 (orchestrator decision): reauth_confirm and the YAML import skip the userinfo check, because reauth cannot edit the stored URL and YAML imports must keep working; the client mapping already closes the crash on those paths.

Purpose: DATA-04 and ROADMAP Phase 4 SC4 promise that the client raises only `TraefikProxyApiError` subclasses. The verifier reproduced a bare `ValueError` for a userinfo URL combined with a bearer token: the config flow ends in "Unknown error" with a traceback, and at runtime HA retries the entry forever with a traceback per attempt.
Output: the mapping in `_request` and `reload_routers`, userinfo rejection in `_check_url_shape`, a real-session regression test, mocked mapping tests, flow tests and a setup-retry test.

Scope guard (M28): WR-03, WR-06..08, IN-01..07 are not touched. In particular the redundant outer timeout in `_validate_input` (WR-06) and the `Auth.header()` guards (WR-07) stay as they are. Converting URL userinfo into basic auth is Phase 7 (auth selector + entry migration).
</objective>

Facts verified at planning time (HEAD a940fbe):
- api.py `_request` (lines 179-210): the network block catches `aiohttp.InvalidUrlClientError` (-> TraefikProxyInvalidUrlError) and `(aiohttp.ClientError, TimeoutError, OSError)` (-> TraefikProxyConnectionError); JSON is decoded after the block (`json.loads`, ValueError -> TraefikProxyPayloadError). `reload_routers` (lines 290-317) has the same two clauses. `raise _status_error(...)` inside the block raises TraefikProxyApiError subclasses, which are not ValueError, so a new ValueError clause cannot swallow them. `aiohttp.InvalidUrlClientError` derives from both ClientError and ValueError, so the existing clauses must stay before the new one.
- Real aiohttp raises the bare ValueError before any socket is opened, for GET and POST, in both the dev venv (aiohttp 3.14.5) and the HA 2026.3.0 venv (aiohttp 3.13.3), and also inside the HA pytest harness with a raw `aiohttp.ClientSession()` (checked with a scratch test). URL userinfo forms that trigger it: `u:p@`, `u@`, `:p@`, `u:@`; `@host` (both empty) carries no credentials and does not trigger it, which matches `urlparse(...).username or urlparse(...).password` truthiness.
- `aioclient_mock` replaces aiohttp's request method, so the real construction error only appears with a real session; mapping tests use `aioclient_mock.get(url, exc=ValueError(...))`.
- config_flow.py `_check_url_shape` (lines 141-151) checks scheme and netloc only; `_validate_input` (154-183) runs it first and is shared by the user (268-295), yaml (298-325), reauth_confirm (338-380) and reconfigure (385-440) steps, each mapping InvalidUrl to `errors["base"] = "invalid_url"`. reauth_confirm probes `entry.data[CONF_URL]`, which its form does not let the user edit; the yaml step validates `STEP_YAML_DATA_SCHEMA(user_input)`.
- `aioclient_mock` matches requests on scheme, raw host and raw path only (test_util/aiohttp.py `match_request`), so a mock registered for `https://traefik.example.com:8080/api/version` also answers a request to `https://u:p@traefik.example.com:8080/api/version`; the call is recorded in `mock_calls` before a registered `exc` is raised. `MockConfigEntry.start_reauth_flow(hass)` exists in both venvs (pattern: tests/test_verify_ssl.py `test_reauth_probe_uses_effective_value`).
- HA's coordinator logs "Unexpected error fetching %s data" with exc_info only for exceptions outside its known set (update_coordinator.py, both venvs); a TraefikProxyApiError becomes UpdateFailed in `_async_setup`, which HA turns into ConfigEntryNotReady without a traceback.
- tests/test_api.py already defines `USERINFO_URL`, `_secret_forms()`, `_client(...)` and `_ERROR_SCENARIOS` used by `test_credentials_never_leak`; tests/test_reconfigure.py uses `entry.start_reconfigure_flow(hass)`.
