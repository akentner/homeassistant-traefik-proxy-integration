## Fix protocol (visual-check findings)

Every finding gets an ID `F-NN` and exactly one of three causes, recorded in the Findings table of `08-VISUAL-CHECK.md` (columns: ID, language, screen, finding, cause, resolution):

1. **cause `code`** — the cause is in this repository (missing or wrong translation, unit, icon, label, behaviour of the integration). Fixed in this plan (D-25): one commit per finding with the message `fix(08-09): F-NN <summary>`, containing the code change and a regression test under `tests/` that fails before the fix. A fix touches only files under `custom_components/traefik_proxy/` and `tests/` (the conditional scope declared in `files_modified`); a fix that would need any other file stops and is reported as a blocker instead. After the commit, run the full gates (dev env with coverage gate, ruff, ruff format, mypy --strict, HA 2026.11.0 venv), restart the HA container (the integration is mounted read-only, a restart loads the change) and retake the affected screenshots. Resolution column: the commit hash and the test id. The SUMMARY lists every touched file under "Deviations (declared scope)".
2. **cause `upstream`** — the cause is outside this repository (Home Assistant core or frontend, Traefik), so no change here can fix it. Recorded in `.planning/phases/08-marketplace-release-readiness/deferred-items.md` (created on the first such finding) with the finding ID, the upstream component, the screenshot name and why it cannot be fixed here. Resolution column: `deferred-items F-NN`.
3. **cause `cosmetic`** — no code cause (core frontend layout, unrelated core repairs, screenshot timing). Resolution column: `listed`.

README and CHANGELOG are not touched here (08-10 describes the result, including fixes made here).
