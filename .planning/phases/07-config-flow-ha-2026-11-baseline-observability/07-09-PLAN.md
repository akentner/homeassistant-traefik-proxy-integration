Facts at planning time (adjusted for 07-01..07-08): `entry.runtime_data` is a frozen `TraefikRuntimeData(client, coordinator, cert_coordinator, entity_manager)`. The client keeps its paginated mode in the private `_paginated` flag (no public accessor). The entity manager keeps per-kind missing-since times in private `_Kind.missing` dicts plus `_stored` for kinds not registered yet; `_serialize_missing` turns such maps into `{kind: {key: ISO}}`; its only public reader is `missing_since(spec, key)`. `TraefikSnapshot` (models.py) holds `version: TraefikVersion` (with `start_date: datetime`), dicts of frozen `Router`/`Service`/`Middleware`/`Entrypoint` dataclasses (tuples, `Status` StrEnum, no backend URLs), `StatusCounts` and problem-name tuples; `HostCertState` (cert_coordinator.py) holds `TraefikCertificate` (datetimes) and `CertSource`. `coordinator.split_url_userinfo` (07-05) strips URL userinfo. Entry data 1.3 keys come from `homeassistant.const` (`CONF_USERNAME`, `CONF_PASSWORD`, `CONF_TOKEN`); `CONF_API_KEY` stays in `const.py` for the migration. The 1.2 migration issue already carries `config_entry_id` (07-02). HA 2026.11 (RESEARCH R-3, confirmation list): `from homeassistant.components.diagnostics import async_redact_data` (REDACTED = "**REDACTED**"; empty strings and None are not redacted); test helper `from pytest_homeassistant.components.diagnostics import get_diagnostics_for_config_entry` (args `hass`, `hass_client`, `entry`); entry-bound issues are deleted on removal, not on unload; re-creating an existing issue keeps a user's dismissal, deleting it does not. `stub_traefik(aioclient_mock, base_url=...)` serves any base URL.
