## Worker decisions (planner, recorded for the SUMMARY)

| Decision | Reason | Alternative not taken |
|---|---|---|
| `HostHeader` is not treated as `Host` | D-05 lists `HostHeader…` among the prefixes that never match; Traefik v3 removed it and a v2 router with it still has a literal Host-header value that rarely carries TLS | Treat `HostHeader(` like `Host(` |
| A negated `!Host(...)` contributes no host | The router does not serve that name; probing it would report a certificate the router never presents | Ignore negation |
| Double-quoted arguments accepted | Traefik accepts backticks and double quotes in rules | Backticks only |
| One normalizer `normalize_host` for rule names and tls.domains (lowercase, one trailing dot, IDNA A-label, charset whitelist, IPv6 literal kept) | SNI and certificate SANs are ASCII A-labels; one normalization makes the later SAN/API matching a plain string comparison | Lowercase only (U-labels would never match a SAN and are invalid SNI values) |
| The cap keeps the first 200 names in sorted order | Deterministic across cycles, so the same 200 hosts keep their entities | Keep the first 200 in router order |
